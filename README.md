# Git IDEA

跨平台可视化 Git 桌面工具，按 IntelliJ IDEA 的布局组织本地仓库工作流。使用 Electron、React、TypeScript 和系统 Git。

当前阶段先交付 Windows 端，提供可直接启动的便携 EXE。macOS/Linux 保留构建入口，原生适配与验收放在后续阶段。

界面采用液态玻璃风格，提供亮色和深黑暗色两套配色。暗色使用中性黑灰背景、半透明玻璃和白色高光。打开「设置」，在顶部「外观模式」预览卡片中选择模式，立即生效并自动保存；下次启动会保留选择。设置页没有“取消”或“保存设置”按钮，修改后可直接关闭；姓名、邮箱输入合法后也立即自动保存，无需移开焦点。

Windows 桌面端支持全局界面缩放：在「设置 → 界面缩放」选择 70%、80%、90%、100%、110%、125%、150%、175% 或 200%，选择后立即应用并自动保存。文字、图标、菜单和面板会一起缩放，重启后保留选择；默认 100%。编辑器字号仍可单独设置。

左侧栏保留参考 IDEA 工具窗口风格生成的项目、日志图标。图标跟随亮暗模式着色，选中工具使用蓝色高亮，保留悬停提示和键盘焦点。右侧按钮栏已移除，提交栏固定显示，可拖动分隔线调整宽度；Ctrl+K 聚焦提交信息。生成素材与提示词见 `docs/sidebar-icons.md`。

## 运行

需要 Node.js 24+ 和 Git 2.37+，确保 `git` 位于系统 PATH。

```sh
npm ci
npm run dev
```

生产模式：

```sh
npm run build
npm start
```

首次打开会显示仓库选择界面，可打开现有仓库、初始化新仓库或从 URL 克隆。开发模式使用当前项目作为默认仓库，桌面程序会记住最近打开的仓库。

## 布局与操作

- 左上：本地项目树，展开目录、打开文件、定位当前文件。文件名、图标和状态字母按 Git 状态着色：红色 U 为未托管，绿色 A 为新增（已加入 Git 暂存区），蓝色 M 为修改，灰色 I 为排除；冲突显示红色 !，未改动文件保持默认颜色。文件夹汇总内部变更，混合状态优先显示冲突、修改、新增、未托管。Git 忽略的文件和目录仍可展开、阅读和编辑；支持嵌套规则与例外文件，已跟踪文件不因忽略规则变灰。
- 中上：多标签单栏编辑器，普通文本和工作区文件默认可编辑，停顿约 500 毫秒自动保存，离开编辑区、切换文件或执行 Git 操作前也会保存；没有编辑模式开关、手动保存按钮或底部工具栏。编辑区保留语法高亮、自动换行和实时行改动标记：红色为删除位置、绿色为新增行、橙色为内容修改、灰色为纯格式变化。保存保留原有 LF / CRLF 换行格式，标记持续到相应内容提交。Ctrl+F 在顶部打开查找面板，Ctrl+H 展开替换，支持大小写、全字、正则、匹配高亮和上下个结果；Enter / Shift+Enter 导航，Esc 关闭，支持单个或全部替换。暂存、历史和已删除文件使用只读单栏差异；二进制和超过读取限制的文件也不可编辑。
- 右上：IDEA 风格提交栏，按“更改”和“未进行版本管理的文件”组织。支持分组/逐文件勾选暂存、部分暂存提示、文件路径、回滚、储藏、查看差异、定位和展开/收起；未托管文件可搜索、分页浏览和按页暂存。下方提供大消息编辑区、修订与草稿恢复、上次提交消息、按仓库保存的消息历史、提交和确认后提交并推送。详见 `docs/commit-panel.md`。暂存和提交时自动排除灰色的纯格式差异，磁盘上的格式保持原样；仅有格式变化时不会创建空提交。当前灰色范围为行尾空格、制表符与文件末尾换行；缩进变化和字符串内部的空白仍按内容修改提交。详见 `docs/editor-changes.md`。
- 左下：本地/远程分支及标签。单击筛选日志，双击检出，行尾菜单可管理分支。
- 中下：IDEA 风格日志工具栏和真实父子图谱。支持文本/哈希、正则、大小写、分支/作者多选、起止日期和多路径组合筛选；提供引用定位、图谱折叠、可选列、显示偏好、原生 Git 提交图索引和提交右键操作。虚拟滚动每批 300 条，最多 50,000 条。详见 `docs/idea-log.md`。
- 右下：提交详情和文件统计。点击文件查看该提交的差异；更多菜单支持拣选、还原、重置、标签。
- 顶部：获取、仅快进拉取、推送、储藏和刷新。底部控制台记录 Git 执行结果；储藏页支持应用、弹出和删除。

分支菜单支持创建、重命名、安全删除、合并和变基；未合并的分支由 Git 拒绝删除。远程仓库通过 Git 面板右上角的 `+` 管理。仓库身份、深浅主题、界面字体、编辑器字体和字号在设置中调整。字体可填写本机已安装字体名称，多个字体使用英文逗号分隔；留空恢复默认，修改立即生效并自动保存，下次启动时恢复。提交者姓名和邮箱在输入完成、离开输入框时自动保存；姓名与邮箱需要完整有效。仅调整外观不要求先配置提交身份。拖动面板分隔线可调整布局。

冲突文件可从提交区打开，直接编辑工作区内容并移除冲突标记，自动保存完成后点击文件旁的「标记已解决」。全部解决后，在提交区继续或中止操作。保存失败会显示原因并保留草稿、暂停切换与 Git 操作，可重试或先复制草稿再重新载入磁盘内容；保存前会检查磁盘内容是否发生变化。关闭窗口时尚未落盘的内容仍受到保护。

## 快捷键

| 操作             | Windows / Linux | macOS   |
| ---------------- | --------------- | ------- |
| 打开仓库         | Ctrl+O          | ⌘+O     |
| 聚焦提交信息     | Ctrl+K          | ⌘+K     |
| 提交             | Ctrl+Enter      | ⌘+Enter |
| 刷新             | Ctrl+R          | ⌘+R     |
| 项目面板         | Ctrl+1          | ⌘+1     |
| Git 日志         | Ctrl+9          | ⌘+9     |
| 文件内查找       | Ctrl+F          | ⌘+F     |
| 文件内替换       | Ctrl+H          | ⌘+H     |
| 立即完成自动保存 | Ctrl+S          | ⌘+S     |

日志聚焦时，Ctrl+L 聚焦查询，Ctrl+F 定位哈希或引用；↑/↓、Home/End、PageUp/PageDown 选择提交，←/→ 导航父/子提交，Ctrl+C 复制哈希，Shift+F10 打开右键菜单。对话框支持 Escape 关闭及 Tab 焦点循环。

## 打包

```sh
npm run package:win     # Windows 便携 EXE
npm run package:mac     # macOS DMG，在 macOS 上构建
npm run package:linux   # Linux AppImage，在 Linux 上构建
```

产物位于 `release/`。项目提供 Windows、macOS、Linux 的 CI 构建与桌面验证流程。macOS 产物默认未签名；正式分发时需配置开发者签名。Windows 和 Linux 默认使用本机架构。Git 不随应用分发，需要在目标系统安装。

若 Electron 二进制下载受网络影响，可临时设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 和 `ELECTRON_CUSTOM_DIR={{ version }}`，再执行 `node node_modules/electron/install.js`。安装过程会校验发行包摘要。

## 验证

```sh
npm test                # 临时真实 Git 仓库和视图模型测试
npm run build           # TypeScript 检查、界面和 Electron 构建
npm run test:desktop    # 生产窗口、沙箱、IPC 与本地 Git 验证
npm run test:package    # Windows 打包资源与当前生产构建逐文件核对
```

安装了 Tabbit Browser 的本机环境可先启动 `npm run dev:web`，再运行 `npm run test:browser`，在真实临时仓库中验收 20 项界面流程。其他环境可按下列手动流程验收。

测试在系统临时目录内创建仓库和本地裸远程，覆盖空仓库、中文/特殊路径、索引和工作区差异、初次提交、修订、重命名、分支/标签、拣选/还原、合并冲突、储藏、克隆与推拉、二进制和大小限制、路径隔离。不会使用任何真实远程账号。

`node scripts/create-playground.mjs` 可创建用于界面验收的真实临时仓库；路径写入忽略目录 `.test-output/playground.json`。其中包含分支、合并、标签、本地裸远程和待提交文件，便于手动走完整流程。

## 本地开发约定

每次项目文件改动完成后必须提交本地 Git；提交信息说明实际改动。详见 `AGENTS.md`。开发服务只绑定 `127.0.0.1`，浏览器版本仅用于本机开发；正式桌面通过沙箱 preload 接口调用 Git。

桌面权限设计参考 [Electron 安全文档](https://www.electronjs.org/docs/latest/tutorial/security)，状态解析使用 [Git porcelain 格式](https://git-scm.com/docs/git-status)。Git IDEA 是独立项目。
