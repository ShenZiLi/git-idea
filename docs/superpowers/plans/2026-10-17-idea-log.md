# IDEA 风格 Git 日志中间页 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 按用户截图复刻 Git 日志中间页的布局与实际操作能力，先计划、后执行。

**Architecture:** 增强现有 `history` / `LogTable` / `graphRows` 流程，继续通过本机 Git 获取真实历史。工具栏、图谱、导航和菜单拆成可维护组件；视图偏好保存在本机、按仓库隔离，查询条件仍由 App 统一管理。保留已确定的固定提交栏、单栏编辑、黑灰液态玻璃和即时设置。

**Tech Stack:** Electron、React、TypeScript、Lucide、系统 Git；不引入 UI 或 Git 运行时依赖。

**Execution:** 用户已要求计划后执行，本会话持续执行；本地 `codex/` 分支工作并本地提交，不推送，不额外请求“是否开始”。按当前开发约束不新增或运行测试；使用构建、代码审阅和界面预览，明确区分这些活动与测试结果。

## 1. 基线与资料

代码基线：`b98617d`。现状只有文本查询、单分支下拉、展开后的作者/起始日/路径、固定列、简易图谱与上下选择。

资料核对日期：2026-10-17，参照 IDEA 2026.2：

- [IDEA Log tab](https://www.jetbrains.com/help/idea/log-tab.html)：中间提交区、工具栏、上下文菜单、图谱与显示选项。
- [IDEA Investigate changes](https://www.jetbrains.com/help/idea/investigate-changes.html)：提交定位与历史浏览。
- [Git log](https://git-scm.com/docs/git-log)：真实筛选、排序、第一父提交、合并筛选和时间字段。
- [Git commit-graph](https://git-scm.com/docs/git-commit-graph)：原生提交图及路径 Bloom 索引。

准确性边界：截图的可见工具栏与日志交互作为本次交付范围；不把所有 IntelliJ 插件、云端 CI、跨仓库、交互式 rebase 等 IDE 平台能力混入本次中间页改动。索引按钮实际构建 Git commit-graph，不冒称 IntelliJ 的专有日志索引引擎。折叠线性提交不删除历史、不改变 Git。

## 3. 数据契约

新增 `shared/log.ts`，现有字段保留，以免破坏分支树与既有调用：

```ts
export interface LogFilters {
  search: string;
  ref: string;
  author: string;
  since: string;
  file: string;
  limit: number;
  refs?: string[];
  authors?: string[];
  paths?: string[];
  until?: string;
  regex?: boolean;
  matchCase?: boolean;
  order?: "date" | "topo";
  firstParent?: boolean;
  noMerges?: boolean;
}
export interface LogPerson {
  name: string;
  email: string;
}
export interface LogLocation {
  hash: string;
  limit: number;
  anchor: boolean;
}
export const LOG_PAGE_SIZE = 300;
export const LOG_MAX_COUNT = 50000;
```

`Commit` 增加可选 `committer/committerEmail/commitDate`，仍保留作者日期 `date`。后端只接受白名单排序值，路径使用现有相对路径校验、参数数组和字面量；多分支取并集，不同筛选类别取交集。

作者多选用实际 email 标识，已有 `author` 字符串仍兼容；所有列表条件均有上限，不能拼接 shell。

## 4. 任务 1：查询与读取接口

**Files:** `shared/log.ts`、`shared/types.ts`、`electron/git.ts`、`electron/api.ts`；需要时新增 `electron/log.ts`。

- [x] 定义上述契约；从旧 `LogPanel.tsx` 导出兼容类型，避免外部破坏。
- [x] 扩展 Git 格式字段，解析 committer 时间且不丢作者时间。
- [x] 原生参数按条件组合：

```ts
const order = params.order === "topo" ? "--topo-order" : "--date-order";
const flags = [
  order,
  ...(params.firstParent ? ["--first-parent"] : []),
  ...(params.noMerges ? ["--no-merges"] : []),
];
const textMode = params.regex ? "--extended-regexp" : "--fixed-strings";
```

不区分大小写时加 `--regexp-ignore-case`。作者选择按字面量转义，避免在正则模式下误解释姓名。日期校验年月日并转成明确本地日边界；`until` 含当天，起止逆序报错。

- [x] 哈希查询遵守当前其他筛选，不再直接绕过作者、日期、路径和分支条件。无效正则返回明确错误，不展示旧结果冒充匹配。
- [x] `logPeople` 从仓库真实作者读取；空仓库返回空列表。
- [x] `logResolve` 仅接受可解析为 commit 的哈希/分支/标签；`logLocate` 计算目标在默认日期序结果中的加载位置；超出上限时返回 `anchor=true`，明确以目标为起点，而非静默跳错。
- [x] `log.index` 调用 `git -c core.commitGraph=true commit-graph write --reachable --changed-paths`，串行处理，只写 Git 管理数据。不可用时显示 Git 原生错误。
- [x] `hasMore` 用额外读取一条判断，不因“刚好 300 条”误报；最大加载数到达时显示明确提示。
- [x] 只提交后端与类型文件，说明命令映射；不运行测试。
