# 输入控件检查与修复

## 范围

本轮针对截图中的搜索框焦点圈套在输入文字上，检查共享输入样式、图标组合输入框、下拉框、表单、提交消息区、代码编辑区及工具栏的布局。

| 严重程度 | 位置 | Before | After | 原因 |
| --- | --- | --- | --- | --- |
| MEDIUM | 日志搜索、分支搜索、分支切换、文件内查找、未托管文件搜索、分支筛选、作者筛选 | 内层输入框有独立圆角和焦点圈，部分文字没有水平留白 | 使用共享 `input-shell` 外框；外框绘制焦点指示，内部输入无边框、无独立圆角和轮廓 | 一个组合控件对应一个可见边界，焦点不会压在文字上 |
| MEDIUM | 日志工具栏、高级筛选、编辑器底栏 | 窄区域继续强制单行，输入和按钮可能挤压或溢出 | 工具栏允许换行；输入和图标有明确的收缩规则，清除按钮保留独立空间 | 大比例缩放和窄面板下保持控件可达 |
| MEDIUM | 日志日期筛选 | 原生日期框强制使用暗色模式 | 继承全局主题 | 亮色模式下原生日期控件与界面一致 |
| LOW | 全局输入默认样式、文件变更行 | 文本框规则覆盖原生单选控件；紧贴图标的文件按钮焦点线内收 | 文本默认样式排除单选/复选控件；文件按钮焦点线外移 | 保留原生选择控件语义，减少图标与焦点线重叠 |

## 实现规则

- 普通表单输入框、提交消息和代码编辑器继续使用自身边界；带图标的组合输入框才使用共享外框。
- 组合外框仅在直接包含的输入或下拉框获得 `focus-visible` 时显示焦点圈。新建分支、清除搜索等相邻按钮使用自身焦点圈。
- 使用现有亮暗色焦点令牌和 2px 轮廓；强制颜色模式使用系统 `Highlight`，不隐藏键盘焦点。
- 控件没有增加焦点动画。边框、图标及文字之间保留内边距，输入内容可以独立滚动。

## 验收记录

记录本轮浏览器实际检查结果；不将静态代码检查视为完整的辅助技术认证。

- 完成全局输入、下拉框、文本区域及焦点相关样式的静态排查；代码编辑区保留 8px / 12px 内边距和独立焦点圈。
- 亮暗模式共检查 32 个输入/焦点状态，覆盖全部七处组合控件、提交消息、日期/路径筛选及设置中的字体、身份、字号和界面缩放字段。组合控件均为内部零边框、无内层轮廓、外框显示焦点；普通表单保留独立轮廓，没有发现控件高度溢出。
- 键盘 Tab 可到达清除搜索及新建分支按钮；按钮聚焦时只显示自身焦点圈，组合输入框不再重复显示焦点。设置的模式单选卡片也保留键盘焦点，原生单选控件未受到文本内边距影响。
- 检查约 288 CSS 像素宽的日志内容区，两种主题下的工具栏、高级筛选、编辑器底栏、提交选项和提交按钮均没有横向溢出。
- 浏览器强制颜色模拟中，外框仍有系统颜色轮廓，内部输入框没有重复轮廓。查看了亮色窄栏及暗色宽栏的实际画面。
- 构建与 TypeScript 检查通过；此轮未执行 Git 提交/推送等业务操作的回归。
