# 文件阅读与行改动标记

## 使用

- 点击普通文本或工作区文件即可编辑，固定为单栏；保留语法高亮、自动换行和行号，不再显示编辑开关、手动保存按钮、整圈蓝色输入框或底栏。
- 停止输入约 500 毫秒后自动写入磁盘；离开编辑区、切换标签或仓库、执行 Git 操作前会等待保存完成。Ctrl+S 可立即完成自动保存，不显示额外按钮或成功通知。
- 保存期间仍能输入，新输入会继续排队保存，不会被旧响应覆盖。中文输入法组合输入完成后再保存。
- 保存失败显示原因并保留草稿，暂停切换与 Git 操作；可重试，或先通过复制按钮保留草稿，再确认重新载入磁盘内容。保存前检查磁盘内容，发现外部修改时不主动覆盖。
- 暂存、历史提交与已删除文件为只读单栏差异；二进制和超过 2 MB 的文件不可编辑。关闭窗口前尚未落盘的内容仍受保护。
- 行号和标记在自动换行与滚动时保持对齐，保存后标记仍保留。

## 查找与替换

- Ctrl+F / ⌘+F 打开编辑区顶部查找栏；Ctrl+H / ⌘+H 展开替换栏；左侧箭头可展开或收起替换。
- 支持区分大小写、全字匹配和正则表达式，显示匹配高亮及当前位置 / 总数。Enter 查找下一个，Shift+Enter 查找上一个，支持循环；Esc 关闭并返回文本。
- 替换支持单个和全部替换，正则替换可引用捕获组（如 `$1`、`$<name>`）。替换也会自动保存，原生撤销可恢复替换前内容。
- 暂存、历史等只读视图支持查找，替换不可用，不会改写工作区或 Git 暂存区。
- 正则在可终止的独立线程中运行；无效或耗时过长时显示提示。最多显示 20,000 个匹配，超出时需缩小范围才能全部替换。

## 颜色

| 颜色 | 含义                                                              |
| ---- | ----------------------------------------------------------------- |
| 绿色 | 新增行                                                            |
| 橙色 | 内容修改，包含缩进和字符串内空白的变化                            |
| 红色 | 删除位置的三角标记，悬停可查看删除行数；文件末尾删除也会标记      |
| 灰色 | 仅行尾空格、制表符或文件末尾换行变化，不加入本应用创建的 Git 提交 |

普通文件与 HEAD 对比，未跟踪的新文件按新增行显示；工作区文件与暂存版本对比。保存不会清空相对于 Git 的标记，提交或刷新基线后会更新。常规 CRLF / LF 转换在行比较中统一处理，保存时继续保留工作区的换行格式。

## 格式变化与提交

暂存时先由 Git 生成候选暂存区，再排除相对于 HEAD 的灰色格式差异；提交前也会对已暂存内容执行相同处理。混有内容修改和纯格式修改的文件会只提交内容改动，格式仍留在工作区。过滤之后没有内容变化时不会创建普通空提交；修订提交信息和合并提交保留 Git 原有语义。

该规则只识别上述文本格式差异，不会运行代码格式化器，也不会忽略缩进、增加或删除空行、引号中的空白或其他文本内容。新增文件、删除文件、二进制、符号链接和子模块继续由 Git 按原方式暂存；超过编辑器读取限制的文件不做文本格式过滤。

暂存区在私有副本中准备，完成后持有 Git 的 index.lock 并确认原暂存区未被其他程序修改，再发布候选暂存区。候选内容准备或发布失败时保留原暂存内容，磁盘文件始终保持原样。仓库的 Git 属性与 clean 过滤器仍由原生 Git add 处理，写入过滤后的对象时不重复运行过滤器。
